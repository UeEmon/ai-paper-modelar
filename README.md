# AI Paper Modelar / 汎用ペーパークラフトジェネレーター

AI Paper Modelarは、写真・スケッチ・公開資料・アイデアを参考に、紙模型のデザインを検討し、基本的な展開図を作成するWebアプリです。**鉄道模型ジオラマ専用ではありません。** 建築物、乗り物、風景、小物、キャラクター、オリジナル作品を制作ジャンルとして選択でき、鉄道模型は選択肢の一つとして引き続き利用できます。

## 初期実装

- BingのWeb検索とWikipediaで対象の名称を検索し、公式サイト・一般ページ・百科事典等の参考情報を一覧表示。架空作品など検索結果がない場合も制作条件の入力を継続できます。
- OpenAI・Gemini・Anthropic・Ollama・ローカルOpenAI互換API（LM Studio等）を切替可能。モデルとAPIキーはブラウザのユーザープロファイルごとに暗号化保存。未設定・ロック中なら定型案を表示。
- 忠実再現、標準デフォルメ、アニメ風、昭和レトロ、簡単組立を選択。
- 縮尺は実寸1/1、1/12、1/24、1/35、1/48、1/72、1/100、鉄道模型向け1/150・1/160・1/80・1/87・1/220、任意1/1〜1/500。
- m・cm・mm単位で元の幅、奥行、高さを入力。建物型・箱型に加え、円柱、円すい／円すい台、正多角柱、正多角すいの展開図をA4実寸PDF・SVGで生成。入力値は内部的にmへ換算するため既存プロジェクトと互換性があります。
- 50mm印刷チェック線、切断・折線・のりしろ表示、タイル分割。
- Docker Composeでローカル起動。
- 手持ち写真・設計図・PDF（JPEG/PNG/WebP/PDF）を最大8点アップロードし、サムネイルで確認・削除。資料ごとに方向とメモを付与。
- **利用者が明示的に許可した場合のみ**画像等のプレビューとPDF抽出テキストを選択中のAIプロバイダーに送信して文章案を作成。

## 起動方法

Docker Desktopを起動したら、リポジトリ直下で:

    cp .env.example .env
    docker compose up -d --build

ブラウザで http://localhost:8086 を開きます。API定義は http://localhost:8086/docs です。
停止コマンド:

    docker compose down

## タブで作業を切り替える

画面上部の6つのタブで機能を選びます。選択したプロジェクトと題材は共通で、上部の作業状況から確認できます。

| タブ | できること |
|---|---|
| 資料・AI提案 | 題材の入力、資料検索、画像/PDFの追加、保存資料の選択、スタイルの検討、AI提案 |
| 基本形状 | 建物・箱・円柱等の形状、寸法、縮尺を指定して展開図を生成。プレビューとPDF/SVG保存も同じタブ |
| 3Dモデル | OBJ/STLの読み込み・展開、専用プレビュー、PDF/SVG保存 |
| 画像→3D | Wikimedia Commonsの画像を検索し、既存の画像対応AIで基本立体を組み合わせた簡易3Dを生成。回転プレビュー・OBJ保存・展開図への受け渡し |
| プロジェクト | 期限付きの一時作業、完成した展開図の再ダウンロード・削除 |
| AI設定 | プロファイルの作成・解除・ロック・削除、クラウド/ローカルAIの設定 |

- タブを切り替えても、入力値・選択ファイル・生成済みのプレビュー・AIの解除状態は維持されます。タブの切替だけでは作業の永続保存は行いません。再読込時の復元は一時作業の有効期限とブラウザ内の暗号化AI設定の仕組みに従います。
- 資料欄の「この3Dモデルを展開」を押すと、自動で「3Dモデル」タブに移動します。AIや資料なしで直接「基本形状」から作り始めることもできます。
- タブにフォーカスすると左右矢印・Home・Endで切り替えられます。ブラウザの戻る/進む、`/#shape`・`/#mesh`・`/#projects`・`/#settings` の直接リンクにも対応します。スマートフォンではタブを2段で表示します。

## 検索資料を設計・展開図に反映する

1. 「資料・AI提案」タブで題材を入力し、「資料検索」を押します。既定でWeb検索の抜粋とWikipediaの概要を取得し、検索語に合う先頭の資料を選択します。検索範囲は「Web＋Wikipedia／Webのみ／Wikipediaのみ」から選べます。各資料の「AIに使う」で、題材に合う資料だけを選んでください。
2. AI設定でプロファイルを解除してから「選択資料からAI設計案を作成」を押します。選択した資料のタイトル・URL・概要をAIに渡し、資料の特徴に沿ったスタイルと基本形状・推定寸法を依頼します。画像/PDFの送信同意とは別に、公開検索資料の選択内容が提案に使われます。
3. 各案に形状・推定寸法・資料の解釈・参照リンクが表示されます。「設計案を基本形状へ反映」で形状、幅・奥行・高さ、屋根と軒の出、多角形の辺数や円すい台の直径比、スタイルを入力欄へ反映し、「基本形状」タブへ移ります。縮尺は利用者の指定を維持し、寸法表示はメートルにそろえます。
4. **AIの寸法は推定値です。** 実測値を確認・修正して「この条件でA4展開図を生成」を押してください。以前のプレビューは案の適用時に消し、変更後の形状・寸法で再生成します。複雑な形や外観・テクスチャの忠実な自動復元は行いません。

AIが未設定・ロック中・接続失敗の場合は定型案であることと、資料を解釈していないことを明示します。形状・寸法のない案は「スタイルのみ適用」と表示します。不正な形状、範囲外・非有限の寸法などはサーバーで除外し、設計欄へは反映しません。参照元リンクはAIが実際に返した有効な資料番号から表示しますが、AIの解釈が正しいことを保証するものではありません。

題材の入力変更・プロジェクト変更・検索失敗では古い検索資料を使いません。題材や資料選択が変わった後に届いた古い提案も破棄します。適用した形状・寸法はプロジェクトの「一時設定を更新」で作業中に保持できます（RAMのみ・再起動後は復元しません）。検索結果・選択資料・AIの根拠表示自体はこのページ内の状態で、プロジェクトには永続保存しません。

### Webを広く検索する

「資料検索の範囲」の既定値は「Web＋Wikipedia」です。追加のAPIキーなしで、Bingの公開RSS検索とWikipedia APIを並行して呼びます。Web検索には公式サイト、博物館、自治体、個人の資料ページ、PDF等が見つかる場合があります。各候補に検索元・ドメインを表示し、選択した資料のタイトル・URL・抜粋・種別をAIへ渡します。Web掲載や検索順位から公式性・正確性を自動認定することはありません。

- Webと百科事典の結果を混ぜ、同じURLを重複表示しないようにして最大8件を表示します。題材の名称が抜粋・タイトルに含まれる候補を優先します。一致の少ない候補は自動選択せず、関連性の確認を案内します。検索品質・網羅性は検索サービスに依存します。
- 片方の検索元が失敗しても利用できた結果を表示し、どの検索元を利用できなかったかを明示します。両方失敗した場合は検索エラーとします。検索範囲を変更すると以前の資料は消し、再検索を求めます。
- 検索ボタンを押すと入力語を選択した検索サービスへ送信します。AIキーや資料の原本は検索サービスへ送信しません。検索結果の抜粋だけを取得し、任意のリンク先本文・画像・PDFをアプリサーバーから取得することはありません。URLはhttp/httpsに限定し、認証情報付きURLや明示的なローカル/プライベートIP等を除外します。
- 各検索元の取得は12秒、応答は512KiBまでに制限します。RSSのDTD・外部エンティティは拒否し、検索元からのリダイレクトにも追従しません。検索結果のHTMLは表示・実行せず、テキストとして扱います。
- BingのRSS検索は将来の形式変更・停止や地域/語句による結果の違いがあり得ます。動作しない場合は画面の警告を確認し、時間をおいて再試行するか「Wikipediaのみ」へ切り替えてください。結果が目的に合わない場合は名称やキーワードを調整し、関連する資料だけを選んでください。

参照: [MicrosoftのRSS検索の案内](https://blogs.bing.com/search/2005/1/RSS-Feeds-for-Search-Results/)。

## 生成AIの設定と秘密情報

1. 画面上部の「AI設定」タブを開き、プロファイル名と12文字以上の固有のパスフレーズで新規作成します。
2. OpenAI / Gemini / Anthropic / Ollama / OpenAI互換（ローカル）を選び、利用権限のあるモデルIDとAPIキー（ローカルでは任意）を入力して「接続を確認して保存・使用」を押します。初期モデルIDは入力例であり、提供状況・権限は各社で確認してください。「モデル一覧を取得」から選ぶか、モデルIDを直接入力できます。
3. 「AI提案」で保存済みの選択先を使用します。API利用料が発生する場合があります。各社のモデルとキーを個別に保持し、キー空欄での再保存は選択先のキーを維持します。
4. 使用後は「ロック」。再読込・画面離脱・プロファイル切替・別タブでの保存変更でもロックされ、解除するまで定型案になります。自動で最後の利用者を解除しません。「使わない」を保存すると定型案になります。
5. プロファイル選択後にパスフレーズで解除できます。「削除」はそのプロファイルの保存済みAI設定・全プロバイダーのキーを削除します。ブラウザのサイトデータ削除でも消えます。**パスフレーズの復旧・端末間同期はありません。**

### モデルIDを一覧から選ぶ

1. プロファイルを解除し、プロバイダーを選びます。クラウドAPIのキー、またはローカルの接続先・任意のキーを入力します。キー欄が空なら選択プロバイダーの保存済みキーを使います。
2. 「モデル一覧を取得」を押し、「モデルを選ぶ」でIDを選択します。モデルIDは未入力でも一覧を取得できます。Ollamaは導入済みモデル、OpenAI互換APIはそのサーバーが返す一覧を表示します。
3. 選んだIDが設定欄へ入ります。「接続を確認して保存・使用」で接続確認後に暗号化保存します。一覧の取得・選択だけでは使用中の設定を変えません。

一覧にないモデル、一覧APIの未対応、閲覧権限不足の場合も、モデルIDを手入力して接続テスト・保存できます。一覧は画像入力と文章生成に対応する、画像→簡易3D向けの候補だけを表示します。3Dファイルを直接生成するモデルの一覧ではなく、画像から部品構成JSONを生成し、アプリがメッシュと展開図を作成する方式です。能力不明・テキスト専用・埋め込み・画像生成専用モデルは除外します。Ollamaは `/api/show` の `vision` + `completion`、LM Studioは同じ接続先の `/api/v0/models` の `type: vlm` を確認します（一覧IDの共通部分のみ）。Anthropicは `capabilities.image_input.supported` を優先。能力情報を返さないクラウドAPIは `app/model_capabilities.py` の公式仕様に基づく保守的な対応ID表を使います。新しいIDは能力確認後に表を更新してください。明示的な非対応情報は対応表より優先します。能力不明モデルは手入力して画像対応テストできます。一覧は複雑な3D形状の再現品質を保証しません。

`POST /api/ai/models` は専用ヘッダーの設定で、OpenAI/Anthropic/OpenAI互換の `/models`、Geminiの `/v1beta/models`、Ollamaの `/api/tags` を参照します。生成・モデル導入は行いません。取得データはページ内だけに保持し、プロファイルのロック、プロバイダー・キー・接続先の変更で破棄します。キーはURL・永続保存・エラー本文へ含めず、応答は `no-store`、ローカルURLの許可リストとリダイレクト拒否も維持します。

GeminiとAnthropicのページ送りは最大5ページ、一覧全体は最大1000件、取得は全体で20秒以内です。Ollamaの能力確認は最大100モデル、同時4件・1件5秒までです。打ち切った場合は一部の一覧であることを表示し、手入力を案内します。

能力仕様: [OpenAI Vision](https://developers.openai.com/api/docs/models)、[LM Studio VLM](https://lmstudio.ai/docs/developer/rest/endpoints)、[Ollama Show](https://github.com/ollama/ollama/blob/main/docs/api.md#show-model-information)。

参照: [OpenAI Models](https://developers.openai.com/api/reference/resources/models/methods/list)、[Gemini Models](https://aistudio.google.com/api-reference/models/list-models)、[Anthropic Models](https://platform.claude.com/docs/en/api/models/list)、[Ollama Tags](https://docs.ollama.com/api/tags)。

### 設定時の接続テスト

- 「接続を確認して保存・使用」は、入力中のプロバイダー・モデル・キー・接続先で短い生成リクエストを送り、成功した後にだけ暗号化保存して有効化します。失敗時は以前の保存内容と使用中の設定を維持し、入力を修正して再試行できます。
- 「テキスト接続テスト」と「画像対応テスト」は保存せずに確認します。成功しても、保存を押すまでは使用中の設定を変えません。「使わない」は接続を行わず保存できます。
- 認証失敗、モデルやAPIの未検出、利用制限、時間切れ、通信・応答の異常を画面に表示します。上流のエラー本文やキーは返しません。テスト中にロック・プロファイル切替・別タブでの変更があれば結果を破棄し、保存しません。
- `POST /api/ai/test` は提案と同じ専用ヘッダーで入力を受け、資料・プロジェクト・題材は送信せず、通常は「Reply OK.」で確認します。`X-AI-Test-Mode: image` は生成した左右2色の小さなJPEGを送り、色の順序が一致するか検証します。正解の色はプロンプトに含めません。画像を無視した「OK」は成功にしません。ローカルAIの画像送信設定を有効にして保存する場合も画像テストを実行し、失敗時は以前の設定を保持します。クラウドAIでは少量のAPI利用料が発生する場合があります。色の認識成功は、複雑な画像や3D生成の品質までは保証しません。
- タイムアウトはテキストがクラウド20秒・ローカル60秒、画像が40秒・120秒。接続先許可リスト、ローカルのプロキシ無効化、リダイレクト拒否、キーの非永続保存、`Cache-Control: no-store` は提案機能と共通です。ローカルモデルの初回読み込みで時間切れになる場合は、モデルを起動してから再試行してください。

### 保存・通信の境界

- `localStorage` の `paper-modelar-ai-v1:<ランダムUUID>` に、プロファイル名・形式バージョン・salt・IV・暗号文を保存します。モデル・プロバイダー・ローカル接続先・画像送信設定・APIキーは AES-GCM 256bit で暗号化。PBKDF2 SHA-256（600,000回、プロファイル固有16byte salt）から鍵を導出し、保存ごとに12byte IVを生成、プロファイルIDを認証データに使います。パスフレーズ・復号鍵・平文キーは永続保存しません。プロファイル名は平文なので秘密情報を入れないでください。
- HTTPS または localhost の Web Crypto が必要です。保存を拒否したブラウザ・破損したデータ・誤ったパスフレーズではキーを使わず、定型案を利用できます。
- 解除中の設定はページのメモリだけに保持。APIキー入力欄は保存・解除・切替後に空にし、再表示しません。同一ブラウザの別タブから保存内容が変更された場合もロックします。
- `POST /api/proposals` に `X-AI-Provider` / `X-AI-Model` / `X-AI-Key` ヘッダーを送り、アプリサーバーが固定の各社HTTPSエンドポイント、またはサーバー側で許可済みのローカルLLM接続先へ転送します。**キーはサーバーのリクエスト処理中に扱いますが、DB・ファイル・環境変数・プロジェクト・URLには保存しません。** サーバーの旧 `AI_PROVIDER` / `*_API_KEY` / `*_MODEL` 環境変数は参照しません。既存の.envやホスティング設定から旧AIキーを削除してください。
- クラウドAPIのキーなし・プロファイル未解除のリクエストは定型案。ローカルLLMは認証なしでも利用できます。別利用者・別リクエストへのキー継承はありません。API設定検証・外部APIエラーは汎用メッセージにし、応答は `Cache-Control: no-store`。キーを含むヘッダー・本文をプロキシ/APM/デバッグログへ記録しないでください。リポジトリに実キーを置かないでください。
- OpenAIへのリクエストでは `store: false` を指定します。各社側の保持・利用条件は契約と設定に従います。参考画像/PDFの送信は引き続き資料送信チェックが必要です。キーやパスフレーズはAIへのプロンプトには含めません。
- これは**ブラウザ内のAI設定分離であり、サーバーのユーザー認証ではありません**。制作プロジェクトの共有構造は従来どおり単独利用向けです。暗号化は保存データを保護しますが、解除中のXSS・悪意あるブラウザ拡張・端末管理者・信頼できないサーバーからは保護できません。共有端末は別のOS/ブラウザアカウントも使ってください。画面には同一オリジン限定のCSPを設定しています。外部公開にはHTTPS・認証・データ隔離が別途必要です。

## ローカルLLM（Ollama / LM Studio等）

LLMを自分で起動し、使用するモデルを読み込んでから、生成AIの設定で以下を選びます。モデルのダウンロード・起動はこのアプリからは行いません。

| 設定 | Ollama | OpenAI互換（LM Studio / llama.cpp / vLLM等） |
|---|---|---|
| プロバイダー | Ollama（ローカル） | OpenAI互換（ローカル） |
| 接続先の例 | `http://localhost:11434` | `http://localhost:1234/v1` |
| モデルID | `ollama list` にある正確な名前（例 `qwen3:8b`） | サーバーで読み込んだ正確なID（例 `publisher/model`） |
| APIキー | 認証なしなら空欄 | 認証なしなら空欄、認証ありならそのキー |
| 通信先 | 接続先 + `/api/chat` | 接続先 + `/chat/completions` |

- 接続先は**ブラウザではなくアプリサーバーから見たURL**です。PC上で直接アプリを起動するなら `localhost`、Dockerから同じPC上のLLMへ接続するなら `http://host.docker.internal:11434` または `http://host.docker.internal:1234/v1` を入力します。ComposeにはLinux向けhost-gatewayの設定も含めています。LLM側がDockerから到達できるインターフェースで待受している必要があります。待受範囲を広げる場合はファイアウォール等で信頼した接続元だけに制限してください。
- **クラウドに置いたアプリサーバーから、ブラウザを開いているPCのlocalhostには接続できません。** ローカル完結で利用する場合はこのアプリとLLMを同じPCで動かしてください。ローカルLLMを使っても「資料検索」は選択した検索範囲に応じてBing・Wikipediaへ接続します。
- 既定では `localhost` / `127.0.0.1` / `[::1]` / `host.docker.internal` のポート11434（ルート）と1234（`/v1`）だけを許可します。接続先URLはブラウザ内で暗号化保存しますが、ブラウザからサーバーの許可リストは変更できません。
- 別ポート・LAN上のLLMを使う場合は、アプリ側の `.env` に `PAPER_MODELAR_LOCAL_AI_URLS=http://192.168.1.20:8000/v1,http://host.docker.internal:11434` のように**許可する完全なベースURLをカンマ区切りで設定**し、アプリを再起動してください。この値は既定の許可リストを置き換えます。空文字ならローカル接続はすべて無効になります。URLはhttp/https・明示的なポート番号が必須で、ユーザー名・パスワード・クエリ・フラグメントを含められません。URL内にキーを埋め込まないでください。接続先を許可する管理者は、接続先とDNSを管理できる信頼した環境だけを指定してください。
- リダイレクト追従と環境変数のHTTPプロキシはローカル接続で無効にしています。許可外の接続先は送信前に拒否し、接続失敗・モデル未導入・JSON応答不正時は定型案に戻ります。クラウドAIへの自動切替はありません。ローカル応答のタイムアウトは120秒、出力上限は2400トークンです（サーバーやモデル側の解釈に依存）。
- 通常はテキストのみ送信します。画像対応モデルの場合だけ「画像対応モデルとして資料画像を送信する」を有効にしてください。資料欄の「資料をAI提案にも利用する」も許可した場合に限り画像（先頭3件）を送ります。画像送信を無効にしたまま資料利用だけを許可した場合は、資料メタデータとPDF抽出テキストを使い、画像解析は行いません。
- 日本語のJSON形式の提案を返せるチャットモデルが必要です。Ollamaは `format: json` と非ストリームの `/api/chat`、互換APIは非ストリームのChat Completionsを使います。モデルの能力・サーバーごとの互換性により提案の品質や画像解析の可否は変わります。ローカルAPIキーも他の設定と同じ暗号化・ロック・削除の対象です。

ローカルAPIの参照: [Ollama Chat](https://docs.ollama.com/api/chat)、[LM Studio Chat Completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions)。

API実装の参照: [OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Gemini generateContent](https://aistudio.google.com/api-reference/generate-content)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages)。

### Docker版でOllamaへ接続できない・一覧を取得できない場合

Docker内の `localhost` はコンテナ自身です。Mac/Windows等のホストPC上で動くOllamaへは、アプリ側の接続先として `http://host.docker.internal:11434` を使います。AI設定の「標準の接続先へ戻す」で、実行環境に合う接続先へ戻せます。モデルIDやAPIキーは変更せず、一覧を取得して接続確認後に保存してください。

標準Dockerイメージでは、既定の許可リストを使用している場合に限り、保存済みの `localhost` / `127.0.0.1` / `[::1]` の標準接続先も `host.docker.internal` として解決します。そのため、以前のブラウザ設定でも一覧取得とAI呼び出しを継続できます。モデル一覧・接続テストの応答で実際の接続先を返し、画面にも反映します。通常のPC上で直接起動する場合は `localhost` のままです。

`PAPER_MODELAR_LOCAL_AI_URLS` を明示している環境では、URLを文字どおり扱い、この自動変換は行いません。コンテナ内でLLMを動かす等の独自構成は、意図したURLを明示して利用してください。許可外の接続先へ自動再試行したり、Ollamaの待受範囲を変更したりすることはありません。

## 検索画像から簡易3Dモデルを作る

1. 「AI設定」で画像に対応するOpenAI/Gemini/Anthropic、またはローカルの画像対応モデルを選んで保存します。ローカルAIでは「画像対応モデルとして資料画像を送信する」も有効にしてください。「画像対応テスト」でテスト画像を読めることを確認できます。ローカル画像設定の保存時にも画像テストを行います。
2. 「画像→3D」タブで検索語を入力し、「画像検索」を押します。空欄なら題材名を使います。画像はWikimedia Commonsの公開APIで最大6件を検索します。日本語で見つからない場合は英語名でも試してください。一般Web資料の検索とは別の画像検索です。
3. 画像を1枚選び、出典リンク・作者・ライセンス等を確認します。「出典と利用条件を確認し、選択画像をAIへ送信して3D化する」をチェックし、完成モデルの高さ（20〜300mm、既定120mm）を指定して生成します。画像は選択中のAIへ送信します。この簡易方式では専用3Dサービスや追加のAPIキーを使いません。外部3D方式は下記を参照してください。クラウドAIでは利用料が発生する場合があります。
4. AIが画像の輪郭と主な特徴を、箱・円柱・円すい/円すい台・切妻屋根の部品構成として推定します。サーバーで数値・形状を検証し、閉じた三角形メッシュへ変換します。回転プレビューはドラッグ/矢印キー、拡大縮小はスライダー/ホイール/＋−で操作できます。
5. 「OBJを保存」でmm単位のモデルを保存できます。元画像の出典・作者・ライセンス情報はOBJのコメントにも記載します。「この3Dモデルの展開図を作る」で3Dモデルタブへ移動し、mm・縮尺1/1で既存のメッシュエンジンへ渡します。生成OBJを期限付きの一時作業へ追加する場合は専用チェックを入れてください。

**これは単一画像からの推定による簡易3Dです。** 実測形状の復元、写真測量、裏面の正確な再現、写真テクスチャの転写は行いません。プレビューの色は部品用の概略色で、OBJは形状のみです。部品は最大10個・円周3〜8分割、生成メッシュは既存の500三角形上限以下で検証します。部品は独立した閉じた形状で、接触部が誤結合しないよう各部品を中心から1%縮小して全体の高さを指定値へ合わせます。部品の重なりや隙間、強度、組立品質は保証しません。必ず試作して接合を調整してください。

画像の権利や被写体の権利が許諾済みと自動判断することはありません。画像の利用条件と3Dモデルの利用条件は出典で確認してください。画像の選択や検索だけではAIへ送信せず、チェックと生成操作がある場合に限って送ります。AI未設定・ロック中・不正なAI応答では、画像由来に見せかけた代替モデルを生成しません。

### 外部3D生成APIと既存AIの切替

「画像→3D」の「3Dの作成方法」で、従来の簡易3D（基本立体の組み合わせ）と外部3D APIを選択できます。簡易3D用のAI設定と外部3D設定は独立して保存します。

| 外部API | 対応モデル | 利用枠 |
|---|---|---|
| Hugging Face Spaces | Microsoft TRELLIS.2 | 無料枠あり。トークン任意、日次上限・待ち行列・サービス停止の可能性あり。契約による追加利用は提供元の条件に従う |
| Meshy | T2.5 / T2 / 7.1 / 6 / 6 Lite | APIキーと有料API利用権限・残高が必要 |
| Tripo | P1 / P2 / v3.1 / v3.0 / v2.5 | APIキーと利用枠・残高が必要 |

1. AI設定でプロファイルを作成または解除し、「外部3D生成API」で提供元・3Dモデル・キー（HFトークン）を設定します。接続テストは残高APIまたはHFの認証/API仕様のみを照会し、モデル生成・課金は行いません。生成権限や品質までは検証しません。
2. 「接続を確認して3D設定を保存」で、同じプロファイル内に他のAI設定と別にAES-GCM暗号化保存します。各提供元のキーを保持し、空欄なら保存済みキーを使います。HFはトークンなしでも接続可能です。
3. 画像検索で1枚選び、外部送信と提供元の利用条件・料金／無料枠に同意して生成します。無料枠でも日次上限があります。生成は最長10分待機し、失敗時の自動再生成はしません。失敗や画面離脱でも提供元で実行・課金される場合があるため、その履歴を確認してから再依頼してください。
4. GLBをRAM内で読み取り、外部バッファ・テクスチャ参照を拒否し、形状を最大400三角形へ調整して指定高さのOBJへ変換します。既存の回転プレビュー・OBJダウンロード・メッシュ展開へ引き継ぎます。最終SVG/PDFだけをアプリサーバーに保存します。

`GET /api/3d/models` は対応表（提供元の公式仕様に基づく）です。モデル一覧APIではないため新モデル追加時に `app/external_3d.py` を更新します。`POST /api/3d/test` と `/api/3d/generate` は `X-3D-Provider / X-3D-Model / X-3D-Key` を使い、LLM提案用ヘッダーには混ぜません。通信先は固定APIと許可済み出力CDNだけ、リダイレクトなし、ダウンロード24MiBまでです。キーや上流エラー本文は応答・ファイルに残しません。

外部サービス内での資料・モデルの保管は提供元の条件に従います。HFのセッション中間データは終了処理を試みますが、提供元内の完全削除は保証しません。3D生成モデルも単一画像からの推定であり、正確な裏面・実測寸法・紙模型の組立品質は保証しません。高密度メッシュの削減で細部が失われる場合があります。

公式仕様: [HF Space API](https://huggingface.co/spaces/microsoft/TRELLIS.2/agents.md)、[ZeroGPU無料枠](https://huggingface.co/docs/hub/en/spaces-zerogpu)、[Meshy Image to 3D](https://docs.meshy.ai/en/api/image-to-3d)、[Meshy残高](https://docs.meshy.ai/en/api/balance)、[Tripo Image to Model](https://developers.tripo3d.ai/en/docs/generation-image-to-model/p)、[Tripoファイル](https://developers.tripo3d.ai/en/docs/files)、[Tripoタスク](https://developers.tripo3d.ai/en/docs/task-query)。

## 画像の取得と保存

- 検索先は固定のCommons API。画像取得はAPIが返した `https://upload.wikimedia.org/wikipedia/commons/…` または `https://thumb.wikimedia.org/wikipedia/commons/…` に限定します。任意のWebページからの画像抽出や、利用者が指定した任意URLのサーバー取得は行いません。
- 画像プレビューはサーバーで取得・検証し、EXIFを除いたJPEGに変換。取得は15秒/4MiB、最大2400万画素、リダイレクト・環境HTTPプロキシは無効です。ブラウザは同一オリジンのプレビューURLだけを使います。
- 検索候補はサーバーメモリで最大24件・15分保持し、プレビュー画像はリクエスト中にのみ処理します。キー・パスフレーズは含めません。生成OBJは応答でブラウザへ渡し、プロジェクトを選んでもサーバーに永続保存しません。画像候補と生成結果は再読込で再利用を保証しません。
- `GET /api/image-model/images?q=…`、`GET /api/image-model/images/{id}/preview`、`POST /api/image-model/generate` を追加。生成は既存の専用AIヘッダー、画像ID、題材名、目標高さ、明示的な送信同意を使います。キーはリクエスト内だけで扱い、エラーへ含めません。
- Ollamaの3D構成生成ではJSON Schemaと非思考モードを使い、構成を短いJSONで返すようにします。画像対応・構造化出力に対応するモデル/サーバーを使ってください。AIの解釈・応答速度・成功率はモデルによって変わります。

画像メタデータの仕様: [MediaWiki Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo)。

## 自分で撮影した写真・設計図・PDFの追加

1. 「YOUR REFERENCES」でファイルを選択（1件15MB以内、画面上で最大8件）。対応拡張子は .jpg / .jpeg / .png / .webp / .pdf。
2. 正面、背面、左右側面、屋根、平面図、細部などを選び、任意のメモを入力して追加します。
3. 画像やPDF1ページ目のサムネイルを確認して、不要なら「削除」。
4. AI連携を使う場合は「資料をAI提案にも利用する」に明示的にチェックを入れ、「AIで案を提案」を押します。

保存動作: プロジェクトを選択しても、原本はディスクに保存しません。JPEGプレビューとPDF先頭5ページの抽出テキスト（最大6,000文字）のみメモリに保持し、15分後に失効します。コンテナ再起動でも消去されます。ブラウザのタブを更新した場合は同じタブ内でアップロードIDを復元します。PDFのAI画像参照は先頭1ページのみ、AIへ渡す画像は最大3件で、それ以外はメタデータと抽出テキストを参照します。公開サーバーにデプロイする場合は先にログイン認証や所有者別データ隔離を実装してください。Docker Composeの既定設定はローカルホスト限定です。

PDFの寸法抽出、図面のトレース、写真からの正確な形状復元、OCR、原本アーカイブは将来の開発対象です。AI推定寸法を実測寸法として使用しないでください。API事業者側のデータ取扱いについても利用規約を確認してください。

## 実装上の制約

- 検索はBingのWeb検索の抜粋とWikipediaの概要情報を使います。一次資料・実寸・立面図・構造図・著作権は未検証です。
- **写真・図面からの3D形状の自動復元、専用の自動パーツ分割、テクスチャ焼込み、画像AI生成はまだありません。OBJ/STLは専用の「3D MESH UNFOLDING」で500三角面以下のモデルを展開できます。**
- 通常の展開図は入力寸法に基づく**建物、箱、円柱、円すい、正多角柱、正多角すいのパラメトリックテンプレート**です。別途3Dメッシュ取込画面からOBJ/STLの簡易三角面展開もできます。ジャンルを「乗り物」「キャラクター」等に切り替えても、その題材に固有の複雑な形状は自動生成されません。AIは作り方の文章案を提案しますが、実物の寸法・造形再現は保証しません。
- スタイル切替は配色・窓の表示等の初期実装です。アニメ風の画像生成は次の段階です。
- 部品の接着構造は試作段階なので、接合検証・追加ののりしろ・組立説明書を改良する必要があります。
- PDFには英語部品名を使います。日本語フォントへの対応は今後行います。

## サーバーには完成した展開図だけを保存

- 永続保存は、基本形状・メッシュ展開で描画した最終SVG/PDFのみ。`PAPER_MODELAR_DATA_DIR/outputs/<SHA256>.svg|pdf` に出力し、同じ内容は重複保存しません。入力JSON・キー・画像・PDF資料・検索結果・生成OBJ/GLB・模型設定の付属ファイルは保存しません。
- 「プロジェクト」タブの「保存済みの展開図」で再ダウンロード・削除できます。`GET /api/outputs`、`GET/DELETE /api/outputs/{id}` でも操作できます。
- プロジェクトは一時作業です。資料原本・プレビュー・抽出テキスト・制作メモ・設定はRAMだけで扱い、操作終了から15分またはサーバー終了時に消去。個別の一時アップロード・画像候補は作成から15分、展開済みジョブは1時間で失効します。30秒ごとの定期処理でも期限切れデータを解放します。再起動後に資料を復元しません。
- 原本の永続保存チェックは廃止。一時作業への追加だけ選べます。HTTPアップロードは16MiBまで、multipartの一時ファイルへの退避も防ぎ、RAMで処理します。プロジェクト資料は全体64MiB・各作業40件・最大100作業までです。
- **更新時の移行:** 起動時に旧版の `projects/`（原本・プレビュー）と `library.sqlite3`・SQLite付随ファイルを削除します。参考資料を残さないためバックアップは作りません。既存の `outputs/` は維持します。削除対象はこのアプリの旧ライブラリの固定パスのみです。
- Dockerの名前付きボリューム `paper_modelar_data` は完成展開図のために引き続き使用します。`docker compose down -v` は展開図も削除します。
- 外部サービスに送った資料は、その事業者の保管条件に従います。このアプリ内での非保存は送信先での即時消去を保証しません。APIキーはブラウザで暗号化保存し、アプリサーバーではリクエスト処理中だけ扱います。
- ローカル単独利用向けです。完成した展開図にも題材名など印刷内容が含まれ、同じアプリの利用者から参照できます。外部公開には認証と所有者分離が必要です。

## 汎用化と従来データの互換性

制作ジャンル（`subject_type`）は `architecture` / `vehicle` / `landscape` / `prop` / `character` / `original` / `railway` / `other` です。図面テンプレート（`template`）は `building`、`box`、`cylinder`、`cone`、`prism`、`pyramid` から選択します。寸法表示単位（`input_unit`）は `m`、`cm`、`mm` から選べ、APIの寸法値自体は従来どおりメートル換算です。以前の保存済みモデルやSenroLabの `/v1/nets` に渡すデータは、新規フィールド未指定なら従来の建物型として動作します。
縮尺を1/1として大きな建物を指定すると100ページ上限に達する場合があります。この場合は縮尺または元寸法を調整してください。

## パラメトリック展開図エンジン（v0.4）

テンプレートは `building` / `box` / `cylinder` / `cone` / `prism` / `pyramid` に対応します。寸法から決定論的に展開図を構築し、AIの推定形状をそのまま切断線にはしません。

- `cylinder`：`width_m` を円直径、`height_m` を側面高さとして、連続側面と上下の円形蓋を出力。
- `cone`：`width_m` を底面直径、`top_ratio` を上面直径÷底面直径（0〜1）として、正確な円すい台の扇形角度を計算。0は尖った円すい、1は円柱。
- `prism`：`width_m` は正多角形の外接円直径、`sides` は3〜12。連続側面と上下の正多角形を生成。
- `pyramid`：`width_m` は正多角形の外接円直径、`sides` は3〜12。底面と三角形側面を生成。
- 接着タブ、折線、切断輪郭、A4分割、印刷用50mm基準線を維持します。
- 展開図生成の上限は100 A4ページ。過大寸法は大量のページを確保する前に拒否します。

仕組み・寸法計算式・接合上の限界は [docs/net-engine.md](docs/net-engine.md) に記載します。重要な模型は縮小試作で接合確認してください。
**紙厚、切断幅、折り目の強度、自由曲面、任意3Dメッシュの最適展開は未対応です。**

## OBJ/STL三角形メッシュ展開（初期メッシュエンジン）

Web画面の「3Dモデル」タブから、OBJまたはバイナリ/ASCII STLファイルを選択し、モデルの座標単位（mm/cm/m）、縮尺（1/1〜1/500）、接着タブを指定して実行します。A4 SVGプレビューとPDF/SVGの保存ができます。制作プロジェクトはRAM内の一時作業です。OBJ/STLの原本はディスクへ保存せず、期限内のみ再利用できます。

- `POST /api/mesh/jobs`（multipart: file, source_unit, scale, glue_tabs）で一時展開ジョブを作成。
- `GET /api/mesh/jobs/{id}/pages/{page}.svg` と `GET /api/mesh/jobs/{id}/template.pdf` でA4実寸展開図を出力。`GET /api/mesh/jobs/{id}` は解析結果、`DELETE` は一時結果の削除。
- OBJは頂点/面、負の相対頂点参照、三角形と多角形の扇形三角分割に対応。STLはASCII/バイナリ両対応。
- 三角形の共通辺を分析して接続できる辺を折り目として配置。2D面の重なりが生じる場合は別の展開島へ分割。
- 分離した面の接合辺にのりしろを生成。切断線・折線・着色面は別レイヤー相当のSVG属性として出力。
- 面数500以下、頂点数20,000以下、ファイル5MB以内、生成A4ページ数100以下。複雑なモデルはCAD/Blender等で事前に面数を削減してください。
- 各座標の長さは単位指定後、縮尺を適用したmmへ変換。**STLファイル自体には単位がないため、読み込み時の指定を必ず確認してください。**
- 境界のある開放メッシュは警告。3面以上が同じ辺を共有する非多様体メッシュ、ゼロ面積面、不正形式は拒否。
- 生成結果はサーバーメモリ内で1時間保存、同時に最大8ジョブ。原本は一時展開ジョブに含めず、プロジェクトに追加しても原本はRAM内の一時保持のみです。最終SVG/PDFだけ永続保存します。

**重要な制限:** これは小規模・三角形メッシュ向けの初期汎用展開エンジンです。3D自己交差、閉じた水密性、法線整合、製造時の精度をすべて保証するものではありません。OBJ多角形の扇形分割は凹多角形の正確な三角分割を保証しません。平面の重なりを避けるため、複数島や大きいのりしろが生じることがあります。山折り/谷折りの区別、面番号対応、テクスチャUV転写、紙厚補正、造形の強度は未対応。必ず試し印刷・組立を行ってください。

### セキュリティ

3Dファイル解析はAPIサーバー内でのみ行い、外部AIサービスへ自動送信しません。保存済みOBJ/STLはAIへの参考画像選択対象から除外します。データを扱うDockerは引き続き127.0.0.1でのみ公開する単独利用向けであり、インターネットに公開する前にユーザー認証・ファイル隔離・サンドボックス等を追加してください。
